# Time Report Reminder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Tauri v2 macOS desktop app that takes over the screen on a schedule and on demand with a comedic frosted-glass overlay, a big pulsing "REPORT YOUR TIME" button, and a Harvest "N DAYS MISSING" counter.

**Architecture:** Tauri v2 (Rust backend + React/Vite WebView frontend). App runs headless in the tray and creates a borderless, always-on-top, fullscreen overlay window on trigger. Animation is a swappable React module selected by `assets-config.json`. Harvest API client lives in Rust; React calls it via Tauri commands. Scheduling is a per-user macOS LaunchAgent that launches the app binary with `--scheduled`.

**Tech Stack:** Rust + Tauri v2, React 19 + Vite, TypeScript (strict), `window-vibrancy` crate, `reqwest` for Harvest, `serde`/`serde_json` for state, `chrono` for date math, Vitest for frontend tests, `cargo test` for Rust tests, launchd for scheduling.

---

## Notes on testing philosophy

This is a desktop GUI app. TDD is applied where it earns its keep: pure logic (Harvest API client, missing-days math, state persistence, `should_trigger` decision logic, animation module registry). Visual / native behaviour (vibrancy, overlay window flags, animation choreography, audio playback, tray icon, global shortcut registration) is verified manually with explicit "do X, see Y" steps, because those don't have meaningful unit tests.

## Notes on Tauri v2 docs

Tauri v2 APIs are still moving. Whenever a step says "register plugin X" or "use API Y", confirm against current docs via context7 (`mcp__plugin_compound-engineering_context7__resolve-library-id` then `query-docs`) before writing the code. Examples in this plan target the API surface as of the Tauri v2 stable line in 2026-06.

Create `src-tauri/src/overlay.rs`:

```rust
use tauri::{AppHandle, Manager, WebviewWindow};
use window_vibrancy::{apply_vibrancy, NSVisualEffectMaterial, NSVisualEffectState};

pub fn show_overlay(app: &AppHandle) -> tauri::Result<()> {
    let win = app
        .get_webview_window("overlay")
        .ok_or_else(|| tauri::Error::WebviewNotFound)?;
    apply_vibrancy_safe(&win);
    win.show()?;
    win.set_always_on_top(true)?;
    win.set_focus()?;
    Ok(())
}

pub fn hide_overlay(app: &AppHandle) -> tauri::Result<()> {
    if let Some(win) = app.get_webview_window("overlay") {
        let _ = win.hide();
    }
    Ok(())
}

fn apply_vibrancy_safe(win: &WebviewWindow) {
    let primary = apply_vibrancy(
        win,
        NSVisualEffectMaterial::HudWindow,
        Some(NSVisualEffectState::Active),
        None,
    );
    if primary.is_err() {
        let _ = apply_vibrancy(
            win,
            NSVisualEffectMaterial::Sidebar,
            Some(NSVisualEffectState::Active),
            None,
        );
    }
    // If both fail, the CSS backdrop-filter fallback in the React layer handles it.
}
```

> **Concept (for the demo):** `NSVisualEffectMaterial` is an AppKit type. The `window-vibrancy` crate uses `objc` bindings to set the native view's material so the OS itself does the blur — much cheaper and more authentic than CSS `backdrop-filter`.

```rust
#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]

mod commands;
mod overlay;

use tauri::{
    menu::{Menu, MenuItem},
    tray::TrayIconBuilder,
    Manager,
};

fn main() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![commands::hide_overlay])
        .setup(|app| {
            let trigger = MenuItem::with_id(app, "trigger", "Trigger now", true, None::<&str>)?;
            let quit = MenuItem::with_id(app, "quit", "Quit", true, None::<&str>)?;
            let menu = Menu::with_items(app, &[&trigger, &quit])?;

            TrayIconBuilder::new()
                .menu(&menu)
                .on_menu_event(|app, event| match event.id.as_ref() {
                    "trigger" => {
                        let _ = overlay::show_overlay(app);
                    }
                    "quit" => {
                        app.exit(0);
                    }
                    _ => {}
                })
                .build(app)?;
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

> **Concept:** `MenuItem::with_id` creates each menu entry; `TrayIconBuilder` hangs the menu off the tray icon. `on_menu_event` is a Rust closure that runs on the main thread when a menu item is clicked.

```ts
export interface AudioConfig {
  calm: string;
  annoying: string;
  switchAtMs: number;
}

export class AudioController {
  private calmAudio: HTMLAudioElement;
  private annoyingAudio: HTMLAudioElement;
  private switchTimer: ReturnType<typeof setTimeout> | null = null;

  constructor(private config: AudioConfig) {
    this.calmAudio = new Audio(config.calm);
    this.calmAudio.loop = true;
    this.annoyingAudio = new Audio(config.annoying);
    this.annoyingAudio.loop = true;
  }

  start() {
    void this.calmAudio.play();
    this.switchTimer = setTimeout(() => {
      this.calmAudio.pause();
      void this.annoyingAudio.play();
    }, this.config.switchAtMs);
  }

  stop() {
    if (this.switchTimer) {
      clearTimeout(this.switchTimer);
      this.switchTimer = null;
    }
    this.calmAudio.pause();
    this.annoyingAudio.pause();
  }
}
```

```rust
use chrono::{Datelike, NaiveDate, Utc, Weekday};
use serde::Deserialize;
use std::collections::BTreeMap;

#[derive(Debug, Deserialize)]
struct TimeEntry {
    spent_date: NaiveDate,
    hours: f64,
}

#[derive(Debug, Deserialize)]
struct TimeEntriesResponse {
    time_entries: Vec<TimeEntry>,
}

pub struct HarvestClient {
    token: String,
    account_id: String,
    http: reqwest::Client,
}

impl HarvestClient {
    pub fn new(token: String, account_id: String) -> Self {
        Self { token, account_id, http: reqwest::Client::new() }
    }

    pub async fn missing_weekdays_this_month(&self) -> Result<u32, String> {
        let today = Utc::now().date_naive();
        let month_start = NaiveDate::from_ymd_opt(today.year(), today.month(), 1).unwrap();

        let url = format!(
            "https://api.harvestapp.com/v2/time_entries?user_id=me&from={}&to={}",
            month_start, today
        );

        let resp = self
            .http
            .get(&url)
            .bearer_auth(&self.token)
            .header("Harvest-Account-ID", &self.account_id)
            .header("User-Agent", "TimeReportReminder (noreply@example.com)")
            .send()
            .await
            .map_err(|e| e.to_string())?;

        if !resp.status().is_success() {
            return Err(format!("Harvest API: {}", resp.status()));
        }

        let body: TimeEntriesResponse = resp.json().await.map_err(|e| e.to_string())?;
        Ok(count_missing_weekdays(&body.time_entries, month_start, today))
    }
}

fn count_missing_weekdays(entries: &[TimeEntry], from: NaiveDate, to: NaiveDate) -> u32 {
    let mut totals: BTreeMap<NaiveDate, f64> = BTreeMap::new();
    for e in entries {
        *totals.entry(e.spent_date).or_default() += e.hours;
    }

    let mut missing = 0u32;
    let mut d = from;
    while d <= to {
        let wd = d.weekday();
        let is_weekday = !matches!(wd, Weekday::Sat | Weekday::Sun);
        if is_weekday {
            let logged = totals.get(&d).copied().unwrap_or(0.0);
            if logged < 8.0 {
                missing += 1;
            }
        }
        d = d.succ_opt().unwrap();
    }
    missing
}
```

```rust
use chrono::{DateTime, Utc};

use crate::state::AppState;

#[derive(Debug, PartialEq)]
pub enum Decision {
    Trigger,
    Skip(SkipReason),
}

#[derive(Debug, PartialEq)]
pub enum SkipReason {
    InMeeting,
    Snoozed,
    NothingMissing,
}

pub fn should_trigger(
    in_meeting: bool,
    state: &AppState,
    missing: u32,
    now: DateTime<Utc>,
) -> Decision {
    if in_meeting {
        return Decision::Skip(SkipReason::InMeeting);
    }
    if state.is_snoozed(now) {
        return Decision::Skip(SkipReason::Snoozed);
    }
    if missing == 0 {
        return Decision::Skip(SkipReason::NothingMissing);
    }
    Decision::Trigger
}

#[cfg(test)]
mod tests {
    use super::*;
    use chrono::Duration;

    fn now() -> DateTime<Utc> { Utc::now() }

    #[test]
    fn meeting_skips_first() {
        let s = AppState::default();
        assert_eq!(should_trigger(true, &s, 99, now()), Decision::Skip(SkipReason::InMeeting));
    }

    #[test]
    fn snoozed_skips() {
        let n = now();
        let s = AppState { snoozed_until: Some(n + Duration::minutes(5)), ..Default::default() };
        assert_eq!(should_trigger(false, &s, 99, n), Decision::Skip(SkipReason::Snoozed));
    }

    #[test]
    fn nothing_missing_skips() {
        let s = AppState::default();
        assert_eq!(should_trigger(false, &s, 0, now()), Decision::Skip(SkipReason::NothingMissing));
    }

    #[test]
```

## Stage 10 — Docs (tech-explainer + demo-script)

- [ ] **Step 1: Write `docs/tech-explainer.md`**

Sections (write real content, not headers):
- "What is Tauri" — Rust binary embeds a `WKWebView`; the React app runs in that webview; Rust handles native bits. Compare to Electron: Tauri ships ~5–15 MB vs Electron's ~150 MB because the webview is the OS-provided Safari engine.
- "Why Rust + WebView" — small binary, native menu bar / tray / vibrancy, type-safe IPC via `invoke`.
- "What's a LaunchAgent" — per-user background task managed by `launchd` (macOS's init system). `StartCalendarInterval` is cron-like. Loaded with `launchctl load`.
- "How macOS vibrancy works" — the OS itself blurs what's behind the window using `NSVisualEffectMaterial`. We call into AppKit via the `window-vibrancy` crate's `objc` bindings.
- "Harvest API call" — a single GET with two auth headers; the missing-days math runs in Rust on the response.
- "Module-swap design" — `assets-config.json` + `animations/types.ts` registry. Drop a new folder under `src/animations/`, register it, change one config line.
- "What I'd build next" — camera/mic in-use detection (TCC permissions + AVFoundation); macOS Focus / Do Not Disturb integration; Developer ID signing + notarisation; configurable schedule in-app; AI-generated character video.
